# Feature Specification: Proctoring Orchestration Layer

**Feature Branch**: `008-proctoring-orchestration`
**Created**: 2026-04-19
**Status**: Draft

## Context
The AI bridge currently emits individual signals from four services (Eye Gaze, Speech, Face, Objects). To provide a meaningful proctoring experience, we need to fuse these signals into high-level **Alerts** and a continuous **Risk Score**. This orchestration layer will also persist all events to a **Session Log** for later review.

## User Scenarios & Testing

### User Story 1 - Multi-Signal Alerting
The system detects multiple suspicious signals and generates a prioritized alert. For example, if no face is detected AND speech is detected, a high-severity alert is raised.

**Acceptance Scenarios**:
1. **Given** the Orchestrator is running, **When** no face is detected for > 5 seconds, **Then** an alert event with type `alert` and code `NO_FACE_DETECTED` is emitted over JSON-RPC.
2. **Given** the Orchestrator is running, **When** a "cell phone" is detected by Object Detection, **Then** an immediate alert code `UNAUTHORIZED_OBJECT` is emitted.

### User Story 2 - Running Risk Score
The system maintains a running risk score (0-100) that fluctuates based on AI signals.

**Acceptance Scenarios**:
1. **Given** a new session starts, **When** signals are normal, **Then** the risk score remains low (e.g., 0-10).
2. **Given** suspicious signals (off-screen gaze, detected objects), **When** these occur frequently, **Then** the risk score increases incrementally.

### User Story 3 - Session Persistence
Every detection, alert, and score update is logged for auditability.

**Acceptance Scenarios**:
1. **Given** an active session `abc-123`, **When** AI events occur, **Then** they are appended as JSON lines to `sessions/abc-123.jsonl`.

## Requirements

### Functional Requirements
- **FR-001**: Implement `python_bridge/orchestrator.py` as a centralized rule engine and event logger.
- **FR-002**: The Orchestrator MUST subscribe to all `DetectionEvent` objects emitted by the router.
- **FR-003**: Implement a configurable **Rule Engine** that supports time-based thresholds (e.g., "event X sustained for Y seconds").
- **FR-004**: Implement a **Risk Scorer** that computes a linear weighted sum of active AI signals into a 0-100 score.
- **FR-005**: Every event received or generated by the Orchestrator MUST be logged to `sessions/<session_id>.jsonl` in JSONL format.
- **FR-006**: Alerts generated by the Orchestrator MUST be emitted over the JSON-RPC interface as `alert` notifications.

### Non-Functional Requirements
- **NFR-001**: The rule engine MUST process events in real-time with negligible latency (< 10ms processing time per event).
- **NFR-002**: Configuration for alert thresholds and weights MUST be loaded from `config.json`.
- **NFR-003**: The Orchestrator MUST handle concurrent events from different AI services without race conditions (using thread-safe logging and state management).

## Clarifications

### Session 2026-04-19

- Q: What mathematical method should be used for the risk score calculation? → A: Linear (Simple weighted sum of active violations).
- Q: How quickly should the risk score decay back to zero when no suspicious signals are detected? → A: Persistent (Returns to zero in 5 minutes of inactivity).
- Q: What storage mechanism should be used for the Session Log? → A: Local JSONL files (One file per session).
- Q: Should Session Log I/O be blocking or non-blocking? → A: Async/Background (Non-blocking I/O).
- Q: What naming convention should be used for generated Alert Codes? → A: Service-based (e.g., GAZE_OFF_SCREEN, SPEECH_DETECTED).

## Assumptions
- The `sessionId` is consistently provided by all AI services.
- The `sessions/` directory is writable by the Python process.
- The Electron frontend is capable of receiving and displaying `alert` notifications.

## Out of Scope
- Server-side synchronization of session logs (this phase handles local logs only).
- Advanced machine learning for anomaly detection (this phase uses rule-based logic).
- UI components for displaying the risk score or alert list (Phase 5).
