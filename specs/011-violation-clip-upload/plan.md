# Implementation Plan: Violation Clip Recording & Upload

**Branch**: `013-violation-clip-upload` | **Date**: 2026-05-05 | **Spec**: [specs/011-violation-clip-upload/spec.md](spec.md)  
**Input**: Feature specification from `specs/011-violation-clip-upload/spec.md`

## Summary

When the AI orchestrator detects a cheating violation during an active exam session, the system automatically captures a 20-second video clip (10s pre-violation + 10s post-violation) as forensic evidence. The clip is encoded as H.264 MP4 and uploaded to Bunny CDN via the Python bridge. A structured `AiProctoringViolationEvent` is then emitted to the LMS backend API. All cloud credentials remain exclusively in the Python bridge process; the Electron renderer only sees the resulting CDN URL.

**Technical approach**: Browser MediaRecorder Web API (renderer) → Electron IPC → JSON-RPC 2.0 stdin/stdout router → ffmpeg-python H.264 encode → Bunny CDN HTTP PUT → LMS backend POST.

## Technical Context

**Language/Version**: JavaScript (Electron 33+ renderer + main) / Python 3.11+  
**Primary Dependencies**: Electron 33+, MediaRecorder Web API, ffmpeg-python, requests 2.32+  
**New Dependency**: `ffmpeg-python` (pip); `ffmpeg` binary on system PATH  
**Storage**: Temp files in `os.tmpdir()` during clip composition (deleted in `try/finally`); Bunny CDN for permanent clip storage; no local disk persistence of clip data  
**Testing**: pytest (Python); manual DevTools console tests (renderer)  
**Target Platform**: Windows desktop (Electron); Python 3.11 subprocess  
**Project Type**: Desktop app (Electron + Python hybrid)  
**Performance Goals**: Clip upload completes within 30 seconds of violation moment; ffmpeg encode < 5 seconds for a 20-second clip at typical webcam resolution (720p)  
**Constraints**: Ring buffer must not exceed `pre_buffer_seconds` × `chunk_duration_ms` memory; BUNNY_API_KEY must never leave the Python process; no disk writes during normal buffer operation  
**Scale/Scope**: One active exam session per machine; one clip at a time (lock-state enforced)

## Complexity Tracking

> Principle II architecture boundary deviation documented here.

| Deviation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| stdin/stdout JSON-RPC (not HTTP to :5050) | clip upload involves writing binary ArrayBuffer to a temp file and forwarding the file path to Python. This is handled in the existing router.py pattern. | Routing a binary upload through Flask HTTP would require multipart form handling — added complexity with no architectural benefit. The stdin/stdout router is already active during every exam session. |
