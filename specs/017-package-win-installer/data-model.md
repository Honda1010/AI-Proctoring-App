# Data Model: Windows Executable Installer with Automated Versioning

**Feature**: `017-package-win-installer`  
**Phase**: 1 — Design

---

## Entities

### 1. Application Version

The single canonical version string governing every release artifact.

| Field | Type | Rules |
|---|---|---|
| `version` | `string` (semver) | Must satisfy `MAJOR.MINOR.PATCH` format. Authoritative copy lives in `package.json`. Mirrored to `config.json["version"]` by `scripts/sync-version.js` after every bump. Never manually edited after `sync-version.js` is in place. |
| `releaseDate` | `string` (ISO 8601 date) | Set at build time; embedded in installer metadata by `electron-builder`. |

**State transitions**:
```
1.0.0  →(version:bump)→  1.0.1  →(version:bump)→  1.0.2  →  ...
```
Bump is always patch-level via `npm version patch`. Minor/major bumps are manual.

---

### 2. Installer Package

The distributable artifact produced by a build run.

| Field | Type | Rules |
|---|---|---|
| `filename` | `string` | Pattern: `Lumina AI Proctoring Setup {version}.exe`. Generated by `electron-builder` from `productName` + `version`. |
| `outputDir` | `path` | Default: `dist/`. Configurable via `electron-builder` `directories.output`. |
| `appId` | `string` | `com.lumina.proctoring` — the Windows Registry upgrade key. Must never change across releases. |
| `bundledComponents` | `enum[]` | `[electron-app, python-bridge-exe, ai-models, config-json]` — all required, all present in every build. |
| `installerSizeEstimate` | `string` | 500 MB – 1 GB (varies with model file sizes). |

---

### 3. Bundled Python Bridge Executable

The frozen output of PyInstaller from `python_bridge/server.py`.

| Field | Type | Rules |
|---|---|---|
| `sourcePath` | `path` | `python_bridge/server.py` — entry point. |
| `specFile` | `path` | `python_bridge/server.spec` — hand-authored, controls `datas`, `hiddenimports`, `binaries`. |
| `outputDir` | `path` | `dist-python/server/` — PyInstaller `--onedir` output. |
| `runtimePath` | `path` | At install time, copied to `<resourcesPath>/python-bridge/`. Executable is `<resourcesPath>/python-bridge/server.exe`. |
| `startupPort` | `integer` | `5050` (from `config.json`). Passed as CLI arg `--port 5050` at spawn time. |

---

### 4. AI Model Assets

Binary files that must be bundled inside the installer (resolved in clarification Q1).

| Field | Type | Rules |
|---|---|---|
| `sourceDir` | `path` | `AI/models/` in repo root. |
| `includedExtensions` | `string[]` | `[".weights", ".cfg", ".names", ".pb", ".onnx"]` |
| `pyinstallerDatasEntry` | `string` | `('AI/models/*', 'AI/models')` — listed in `server.spec`. |
| `runtimePath` | `path` | Resolved relative to the frozen executable's `sys._MEIPASS` at runtime. |

---

### 5. Build Run

A single execution of the full build pipeline.

| Field | Type | Rules |
|---|---|---|
| `triggeredBy` | `string` | `npm run release` or individual step commands. |
| `versionAtBuildTime` | `string` (semver) | Read from `package.json` at the start of `build:electron`. Must match `config.json["version"]` (enforced by `version:sync`). |
| `outputs` | `path[]` | `dist/Lumina AI Proctoring Setup {version}.exe` |
| `buildWorkDirs` | `path[]` | `dist-python/` (PyInstaller output), `build-python/` (PyInstaller work cache) — excluded from git. |

---

### 6. Backend Startup Health Check

Runtime entity — tracks whether the Python bridge came up cleanly after app launch.

| Field | Type | Rules |
|---|---|---|
| `healthEndpoint` | `url` | `http://127.0.0.1:5050/health` |
| `maxRetries` | `integer` | `10` |
| `retryIntervalMs` | `integer` | `1000` (1 second between polls) |
| `status` | `enum` | `pending` → `healthy` → (if all retries exhausted) `failed` |
| `onFailed` | `action` | Display error dialog (FR-014); block navigation to exam. |
